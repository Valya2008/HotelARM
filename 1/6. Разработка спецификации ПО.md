# 6. Спецификация программного обеспечения

## 1. Введение
Данный документ представляет собой детальную спецификацию программного обеспечения **«Автоматизированное рабочее место (АРМ) администратора отеля»**.
Система предназначена для комплексной автоматизации учета гостей, управления номерным фондом и бронированиями, контроля графика технического персонала и анализа финансовой деятельности гостиничного учреждения.
Спецификация определяет архитектуру системы, требования к пользовательским и программным интерфейсам, описание ключевых алгоритмов и ограничений реализации.  

## 2. Общее описание
Программное обеспечение обеспечивает решение следующих задач:  
•   **Локальное хранение данных:** Безопасное хранение информации в СУБД SQLite без необходимости сетевого подключения.  
•   **Многопользовательская работа:** Реализация ролевой модели доступа (Администратор/Тех. персонал).  
•   **Управление бронированиями:** Автоматизация резервирования номеров с проверкой конфликтов.  
•   **Финансовый мониторинг:** Сбор и визуализация статистики по доходам и загрузке отеля.  

Система функционирует исключительно локально, что гарантирует высокую скорость отклика и независимость от внешних облачных сервисов.

## 3. Требования к интерфейсам

### 3.1 Пользовательский интерфейс
Графический интерфейс системы реализован на базе технологии **Windows Forms**. Программный комплекс включает в себя следующие графические окна:
1.  **Окно аутентификации:** Поле ввода логина и пароля с механизмом защиты от несанкционированного доступа.
2.  **Главное меню:** Динамическая форма, отображающая доступные модули (Гости, Номера, Бронирования, Аналитика, График персонала, Тех. персонал) в зависимости от роли пользователя.
3.  **Модуль «Управление данными»:** Универсальное окно для создания и изменения сущностей (гостей, номеров, бронирований, сотрудников).
4.  **Интерактивный график персонала:** Табличная сетка для отображения и редактирования смен сотрудников.
5.  **Панель аналитики:** Окно с графическими элементами для отображения выручки и загруженности отеля.

### 3.2 Внешние интерфейсы
Взаимодействие с системными ресурсами ОС Windows осуществляется для:
•   Загрузки и сохранения файла базы данных `*.db`.
•   Логирования системных событий (ошибки доступа, сбои БД).

## 4. Описание программных модулей
Система логически разделена на следующие функциональные блоки:
1.  **Подсистема разграничения доступа и навигации:**  
    •   **Authorization (FormLogin):** Форма входа, первичная проверка учетных данных.
    •   **Menu (FormMenu):** Главный узел управления, который динамически перестраивается под роль пользователя.
    •   **DatabaseHelper:** Технический модуль, «сердце» программы, через который проходят все запросы к базе данных SQLite.

2.  **Подсистема учета и детализации (Реестры):**
    •   **Guests (FormGuests), Rooms (FormRooms), Bookings (FormBookings), Staff (FormStaff):** Основные журналы со списками соответствующих сущностей.
    •   **GuestEdit, RoomEdit, BookingEdit, StaffEdit:** Модальные формы для создания, просмотра и редактирования детальной информации.

3.  **Операционная подсистема (Активные действия):**
    •   **StaffSchedule (FormStaffSchedule):** Основная форма-планировщик для работы с графиком персонала.

4.  **Аналитическая подсистема:**
    •   **Analytics (FormAnalytics):** Модуль сбора данных, который обращается к таблицам бронирований и номеров для вывода итоговых цифр выручки и загруженности отеля.

## 5. Алгоритмы системы

### 5.1 Алгоритм проверки прав доступа
1.  **Старт:** После успешной авторизации глобальной переменной (или свойству) UserRole присваивается значение из базы данных («Admin» или «TechStaff»).
2.  **Инициализация меню:** При загрузке главной формы (FormMenu_Load) запускается цикл проверки доступности элементов.
3.  **Условие:** Если UserRole равно «TechStaff»:
    •   Кнопки вызова форм «Гости», «Номера», «Бронирования», «Аналитика», «Тех. персонал» переводятся в состояние Enabled = false (неактивны).
    •   В форме «График персонала» кнопки редактирования смен (если есть) также блокируются.
4.  **Результат:** Тех. персонал видит только те кнопки, которые относятся к его прямой деятельности (просмотр графика).

### 5.2 Алгоритм расчета загрузки отеля и дохода
1.  **Загрузка номеров:** Система подсчитывает количество номеров в таблице `Rooms` со статусом "Занят" и "Свободен", а также общее количество номеров.
2.  **Расчет дохода:** Система суммирует `Стоимость` всех бронирований из таблицы `Bookings` для получения общего дохода.
3.  **Результат:** Данные отображаются в форме `FormAnalytics` в числовом и графическом виде.

## 6. Требования к данным
•   **Хранение:** Все данные хранятся в реляционной базе данных SQLite.
•   **Целостность:** Реализована через систему внешних ключей (FOREIGN KEY). Например, невозможно удалить гостя, если за ним закреплены активные бронирования, или удалить номер, который имеет текущие бронирования.

## 7. Требования к верификации
Верификация ПО проводится в два этапа:  
1. **Модульное тестирование:** Проверка корректности работы методов валидации данных (формат телефона, дат бронирования, расчет стоимости).
2. **Интеграционное тестирование:** Проверка связей (например, корректное обновление статуса номера после создания/завершения бронирования).

## 8. Заключение
Данная спецификация является основополагающим документом для разработки и тестирования АРМ Администратора отеля.
Она гарантирует, что реализованный функционал соответствует заявленным требованиям предметной области.
