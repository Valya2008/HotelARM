# Описание прецедентов #
### Прецедент  №1: Аутентификация пользователя ###
| Раздел | Описание |
| --- | --- |
| ID | UC-01 |
| Название | Аутентификация пользователя в системе |
| Цель | Получить безопасный доступ к функционалу АРМ согласно роли (Администратор или Тех. персонал). |
| Актор | Администратор / Тех. персонал |
| Предварительные условия | 1. Приложение запущено.<br> 2. В базе данных SQLite существуют учётные записи пользователей. |
| Основной поток | 1. Пользователь вводит Логин и Пароль.<br> 2. Система проверяет данные в таблице Users.<br> 3. При совпадении данных определяется роль (Admin/TechStaff).<br> 4. Открывается главное меню с набором функций, доступных для этой роли. |
| Исключения | • Неверные данные: Вывод ошибки «Неверный логин или пароль».<br> • Пустые поля: Блокировка входа до заполнения всех полей. |
| Постусловия | Пользователь авторизован и получил доступ к интерфейсу согласно своим правам. |

### Прецедент №2: Управление базой гостей ###
| Раздел | Описание |
| --- | --- |
| ID | UC-02 |
| Название | Управление данными гостей |
| Цель | Ведение актуального реестра посетителей отеля. |
| Актор | Администратор |
| Основной поток | 1. Переход в раздел «Гости». 2. Поиск гостя по ФИО или номеру паспорта. 3. Выполнение CRUD-операций: добавление нового, редактирование профиля или удаление. 4. Просмотр полной информации о госте. |
| Исключения | • Ошибки ввода: ввод некорректных символов или неполных данных. |
| Постусловия | База данных гостей обновлена и сохранена в SQLite. |

### Прецедент №3: Управление номерами и бронированиями ###
| Раздел       | Описание                                                                 |
|--------------|--------------------------------------------------------------------------|
| **ID**       | UC-03                                                                    |
| **Название** | Управление номерным фондом и бронированиями                              |
| **Цель**     | Контроль доступности номеров и регистрация фактов бронирования.             |
| **Актер**    | Администратор                                                            |
| **Основной поток** | 1. Просмотр списка номеров и их статусов.<br> 2. Добавление, редактирование или удаление номеров.<br> 3. Создание нового бронирования: выбор гостя, номера, дат заезда/выезда.<br> 4. Автоматический расчет стоимости бронирования.<br> 5. Изменение статуса бронирования (ожидает, подтверждено, завершено, отменено). |
| **Исключения** | • Конфликт бронирования: Попытка забронировать занятый номер на пересекающиеся даты.<br> • Удаление: Запрет на удаление номера с активными бронированиями. |
| **Постусловия** | Информация о бронировании зафиксирована в системе. Статус номера обновлен. | |    

###  Прецедент №4: Управление техническим персоналом ###
| Раздел       | Описание                                                                 |
|--------------|--------------------------------------------------------------------------|
| **ID**       | UC-04                                                                    |
| **Название** | Управление данными о тех. персонале                                       |
| **Цель**     | Вести учет сотрудников (уборщиков, ремонтников) и их учетных записей для доступа к АРМ. |
| **Актер**    | Администратор                                                            |
| **Предварительные условия** | 1. Администратор авторизован в системе.<br> 2. Открыт модуль "Тех. персонал". |
| **Основной поток** | 1. Администратор видит список всех зарегистрированных сотрудников.<br> 2. Добавление: Нажимает "Добавить сотрудника", указывает ФИО, должность, телефон, логин.<br> 3. Редактирование: Выбирает сотрудника, изменяет его данные или учетную запись.<br> 4. Удаление: Выбирает сотрудника, подтверждает удаление.<br> 5. После любого действия, список сотрудников обновляется. |
| **Исключения** | • Удаление сотрудника: Если сотрудник имеет активные учетные записи, система блокирует удаление с уведомлением.<br> • Попытка создать дубликат логина: Система выдает ошибку, если логин уже занят. |
| **Постусловия** | Список технического персонала актуализирован. Учетные записи созданы/изменены/удалены. |

###  Прецедент №5: Планирование и просмотр графика персонала ###
| Раздел       | Описание                                                                 |
|--------------|--------------------------------------------------------------------------|
| **ID**       | UC-05                                                                    |
| **Название** | Планирование и просмотр графика персонала                                  |
| **Цель**     | Организация рабочих смен сотрудников и предоставление им доступа к расписанию. |
| **Актер**    | Администратор / Тех. персонал                                            |
| **Основной поток** | 1. Администратор выбирает дату, сотрудника и устанавливает тип смены (Утро, День, Вечер).<br> 2. Администратор проверяет систему на отсутствие пересечений в графике.<br> 3. Администратор сохраняет изменения в графике.<br> 4. Тех. персонал просматривает свой график без возможности редактирования. |
| **Исключения** | • Конфликт смен: Попытка назначить сотруднику две смены на один день.<br> • Попытка создания дубликата логина: Система выдает ошибку, если логин уже занят. |
| **Постусловия** | График персонала актуализирован. Учетные записи созданы/изменены/удалены. |

###  Прецедент №6: Просмотр аналитики и отчетности ###
| Раздел       | Описание                                                                 |
|--------------|--------------------------------------------------------------------------|
| **ID**       | UC-06                                                                    |
| **Название** | Просмотр аналитических данных                                              |
| **Цель**     | Получение отчетов о финансовой деятельности и загруженности отеля.            |
| **Актер**    | Администратор                                                            |
| **Основной поток** | 1. Администратор переходит в раздел "Аналитика".<br> 2. Система отображает общее количество номеров, количество свободных номеров.<br> 3. Система выводит информацию об общем доходе отеля.<br> 4. Отображает диаграмму распределения номеров по типам. |
| **Исключения** | • Нет данных: Если в базе отсутствуют данные для формирования отчета. |
| **Постусловия** | Информация представлена в виде числовых данных или графиков на экране. |
