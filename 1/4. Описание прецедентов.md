# Описание прецедентов #
### Прецедент №3: Управление номерами и бронированиями ###
| Раздел | Описание |
| --- | --- |
| ID | UC-01 |
| Название | Аутентификация пользователя в системе |
| Цель | Получить безопасный доступ к функционалу АРМ согласно роли (Администратор или Тех. персонал). |
| Актор | Администратор / Тех. персонал |
| Предварительные условия | 1. Приложение запущено.<br> 2. В базе данных SQLite существуют учётные записи пользователей. |
| Основной поток | 1. Пользователь вводит Логин и Пароль.<br> 2. Система проверяет данные в таблице Users.<br> 3. При совпадении данных определяется роль (Admin/TechStaff).<br> 4. Открывается главное меню с набором функций, доступных для этой роли. |
| Исключения | • Неверные данные: Вывод ошибки «Неверный логин или пароль».<br> • Пустые поля: Блокировка входа до заполнения всех полей. |
| Постусловия | Пользователь авторизован и получил доступ к интерфейсу согласно своим правам. |

### Прецедент №3: Управление номерами и бронированиями ###
| Раздел | Описание |
| --- | --- |
| ID | UC-02 |
| Название | Управление данными гостей |
| Цель | Ведение актуального реестра посетителей отеля. |
| Актор | Администратор |
| Основной поток | 1. Переход в раздел «Гости». 2. Поиск гостя по ФИО или номеру паспорта. 3. Выполнение CRUD-операций: добавление нового, редактирование профиля или удаление. 4. Просмотр полной информации о госте. |
| Исключения | • Ошибки ввода: ввод некорректных символов или неполных данных. |
| Постусловия | База данных гостей обновлена и сохранена в SQLite. |

### Прецедент №3: Управление номерами и бронированиями ###
|----------------|--------------------------------------------------------------------------|
| ID             | UC-03                                                                   |
| Название       | Управление номерным фондом и бронированиями                                      |
| Цель           | Контроль доступности номеров и регистрация фактов бронирования.                         |
| Актор          | Администратор                                                           |
| Основной поток  | 1. Просмотр списка номеров и их статусов. <br>2. Добавление, редактирование или удаление номеров. <br>3. Создание нового бронирования: выбор гостя, номера, дат заезда/выезда. <br>4. Автоматический расчет стоимости бронирования. <br>5. Изменение статуса бронирования (ожидает, подтверждено, завершено, отменено). |
| Исключения     | • Конфликт бронирования: Попытка забронировать занятый номер на пересекающиеся даты. <br>• Удаление: Запрет на удаление номера с активными бронированиями. |
| Постусловия | Информация о бронировании зафиксирована в системе. Статус номера обновлен. |
